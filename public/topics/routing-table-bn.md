## Step 1: রাউটিং টেবিল কী?

**রাউটিং টেবিল** হলো কার্নেলের ফরোয়ার্ডিং সিদ্ধান্ত গ্রহণের ডাটাবেস।

প্রতিবার একটা প্যাকেট এলে, কার্নেল এই টেবিল দেখে সিদ্ধান্ত নেয়:
• গন্তব্যটা কি **লোকাল** (সরাসরি ডেলিভারি)?
• গন্তব্যটা কি **রিমোট** (একটা গেটওয়েতে ফরোয়ার্ড করতে হবে)?
• প্যাকেটটা কোন **ইন্টারফেস** দিয়ে বের হবে?

এটাকে একটা **রোড ম্যাপ** বলে চিন্তা করো — কার্নেল গন্তব্য খুঁজে সেরা রুট বাছাই করে।

## Step 2: কানেক্টেড রুট

যখন তুমি একটা ইন্টারফেসে একটা IP এড্রেস কনফিগার করো, কার্নেল **স্বয়ংক্রিয়ভাবে** একটা কানেক্টেড রুট যোগ করে।

`192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.10`

এর মানে: "আমি 192.168.1.0/24-র যেকোনো ডিভাইসে eth0 দিয়ে সরাসরি পৌঁছাতে পারি — কোনো গেটওয়ে লাগে না।"

কানেক্টেড রুটের **সবচেয়ে কম মেট্রিক** (সর্বোচ্চ অগ্রাধিকার) থাকে কারণ সেগুলো সরাসরি সংযুক্ত।

## Step 3: স্ট্যাটিক রুট

অ্যাডমিনিস্ট্রেটররা ব্যবহার করে রুট ম্যানুয়ালি যোগ করতে পারেন:

`ip route add 10.0.0.0/8 via 192.168.1.1`

এটা কার্নেলকে বলে: "10.0.0.0/8 নেটওয়ার্কে যেকোনো কিছুতে পৌঁছাতে হলে, 192.168.1.1 গেটওয়েতে প্যাকেট পাঠাও।"

স্ট্যাটিক রুট কার্যকরী হয় যখন:
• তোমাকে একটা **নির্দিষ্ট রিমোট নেটওয়ার্কে** পৌঁছাতে হবে
• **একাধিক পথ** আছে এবং তুমি কোনটা ব্যবহার হবে সেটা নিয়ন্ত্রণ করতে চাও
• তুমি ডায়নামিক রাউটিং প্রোটোকল ছাড়াই একটা **ল্যাব বা ছোট নেটওয়ার্ক** তৈরি করছো

## Step 4: ডিফল্ট রুট

**ডিফল্ট রুট** (0.0.0.0/0) হলো সব কিছু ধরার এন্ট্রি:

`default via 192.168.1.1 dev eth0`

যখন কোনো নির্দিষ্ট রুট গন্তব্যের সাথে ম্যাচ করে না, কার্নেল ডিফল্ট রুট ব্যবহার করে। এটা যেন বলছে "বাকি সবকিছু এই গেটওয়েতে পাঠাও।"

প্রতিটা ইন্টারনেট-সংযুক্ত হোস্টের একটা ডিফল্ট রুট লাগে — ছাড়া, তুমি শুধু সরাসরি সংযুক্ত নেটওয়ার্কেই পৌঁছাতে পারবে।

## Step 5: রুট লুকআপ অর্ডার

কার্নেল সেরা রুট খুঁজতে **লংগেস্ট প্রিফিক্স ম্যাচ** ব্যবহার করে:

1. গন্তব্য IP সব রুটের সাথে তুলনা করে
2. **দীর্ঘতম ম্যাচিং প্রিফিক্স** থাকা রুট জিতে
3. যদি একাধিক রুটের একই প্রিফিক্স লেন্থ থাকে, **সবচেয়ে কম মেট্রিক** থাকা রুট ব্যবহার হয়
4. যদি এখনো টাই হয়, কার্নেল রাউন্ড-রবিন (ইকুয়াল-কস্ট মাল্টিপাথ) ব্যবহার করতে পারে

**উদাহরণ:**
`Destination: 10.5.5.5`
`10.0.0.0/8 (ম্যাচ হয়) → via 192.168.1.1`
`0.0.0.0/0 (ম্যাচ হয়) → via 192.168.1.1`
**বিজয়ী: 10.0.0.0/8** (8-বিট প্রিফিক্স > 0-বিট প্রিফিক্স)

## Step 6: রুট দেখা

রাউটিং টেবিল দেখার জন্য ব্যবহার করো:

`ip route show` — আধুনিক Linux কমান্ড
`route -n` — পুরাতন কমান্ড (একই আউটপুট)

**আউটপুট ফরম্যাট:**
`192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.10`
`10.0.0.0/8 via 192.168.1.1 dev eth0`
`default via 192.168.1.1 dev eth0`

প্রতিটা লাইন দেখায়: গন্তব্য, গেটওয়ে (যদি রিমোট হয়), ইন্টারফেস, এবং ঐচ্ছিক প্যারামিটার যেমন মেট্রিক ও প্রোটোকল।

## Step 7: রাউটিং টেবিল সারসংক্ষেপ

**মূল কথা:** রাউটিং টেবিল হলো কার্নেলের প্যাকেট ফরোয়ার্ড করার **রোড ম্যাপ**।

কীভাবে কাজ করে:
1. **কানেক্টেড রুট** — IP কনফিগার করলে অটো-অ্যাড হয়
2. **স্ট্যাটিক রুট** — অ্যাডমিনিস্ট্রেটররা ম্যানুয়ালি যোগ করেন
3. **ডিফল্ট রুট** — ম্যাচ না হওয়া গন্তব্যের জন্য সব কিছু ধরে
4. **লংগেস্ট প্রিফিক্স ম্যাচ** — সবচেয়ে নির্দিষ্ট রুট নির্বাচন করে

**কেন গুরুত্বপূর্ণ:**
• কানেক্টিভিটি সমস্যা ট্রাবলশুট করা
• কেন প্যাকেট একটা নির্দিষ্ট পথে যায় সেটা বোঝা
• মাল্টি-হোমড সিস্টেম (একাধিক NIC) কনফিগার করা
• ফায়ারওয়াল ও নেটওয়ার্ক সিকিউরিটি সেটআপ করা

**কমান্ড:**
`ip route show` — রুট দেখো
`ip route add` — রুট যোগ করো
`ip route del` — রুট মুছো
`ip route get 8.8.8.8` — কোন রুট ব্যবহার হচ্ছে সেটা পরীক্ষা করো
